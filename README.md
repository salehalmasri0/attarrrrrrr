# العطار — نظام مراقبة وأداء زيارات المنسّقين

نظام كامل (Frontend فقط) لإدارة وتتبّع زيارات منسّقي المبيعات: تسجيل دخول
بدورين (إدارة / منسّق)، بدء وإنهاء الزيارات بموقع GPS وصور، جدولة يومية
وشهرية، حساب خصومات وتقييم أداء، لوحة مراقبة حية، تقارير Excel، وسجل عمليات
كامل. يعمل بالكامل من المتصفح (بدون خادم Node/PHP) ويستخدم **Firebase
Firestore** كقاعدة بيانات سحابية، بحيث يشتغل بنفس البيانات لحظيًا على أي
جهاز (موبايل أو حاسوب) وعلى **Safari وGoogle Chrome** على حدٍّ سواء.

الملف الواحد، فلا يوجد أي تغيير في المنطق أو الميزات — فقط تنظيم + إصلاحات
موضّحة أدناه.

## 2. أهم الإصلاحات في هذه النسخة

- **إعادة هيكلة كاملة**: من ملف HTML واحد (2160 سطر) إلى مشروع منظّم بملفات
  منفصلة (HTML / CSS / JS لكل قسم) يسهل قراءته وتعديله ورفعه على GitHub.
- **تشفير كلمات المرور وPIN**: كانت مخزّنة كنص عادي (plain text) في قاعدة
  البيانات — الآن تُخزَّن كبصمة SHA-256، مع ترقية تلقائية صامتة لأي حساب
  قديم عند أول تسجيل دخول ناجح (لا حاجة لإعادة إدخال شيء يدويًا).
- **تفعيل العمل بدون اتصال فعليًا**: كان الكود القديم يذكر في تعليق أن
  Firestore "يفعّل تخزين مؤقت تلقائيًا"، لكنه لم يكن مفعّلاً فعليًا. الآن
  `enablePersistence` مفعّل فعلاً، فيقدر المنسّق يكمل خطوات الزيارة بدون
  إنترنت وتتزامن تلقائيًا عند عودة الشبكة.
- **قواعد أمان Firestore** (`firestore.rules`) موثّقة بوضوح مع خطوات لتقوية
  الحماية (راجع القسم 5 أدناه — هذا مهم جدًا قبل الاستخدام الفعلي).
- **تحسين تجربة تعديل PIN المنسّق**: الحقل يظهر فارغًا عند التعديل بدل عرض
  القيمة المشفّرة، مع خيار تركه فارغًا للإبقاء على PIN الحالي.

## 3. التشغيل محليًا (قبل الرفع)

⚠️ **لا تفتح `index.html` بالنقر المزدوج مباشرة من الجهاز (file://)** — كل
من تسجيل الدخول (تشفير SHA-256) وتحديد الموقع GPS وFirestore تتطلب "سياق
آمن" (HTTPS أو localhost) ولن تعمل بشكل صحيح مع file://. شغّل خادمًا محليًا
بسيطًا بدلاً من ذلك:

```bash
cd attar-visits
python3 -m http.server 8080
# افتح المتصفح على http://localhost:8080
```

أو بأي أداة مشابهة (`npx serve`, VS Code Live Server، إلخ).

**بيانات الدخول الافتراضية** (غيّرها فورًا من "الإعدادات → حسابات الإدارة"
بعد أول دخول):
- اسم المستخدم: `admin`
- كلمة المرور: `admin123`

## 4. رفع المشروع على GitHub — خطوة بخطوة

### أ) تجهيز حساب GitHub ومستودع جديد
1. سجّل دخول على [github.com](https://github.com).
2. اضغط **+** أعلى الصفحة → **New repository**.
3. اختر اسمًا (مثلاً `attar-visits`)، اتركه **Public** أو **Private** حسب
   رغبتك (راجع القسم 5 قبل اختيار Public)، **لا** تفعّل "Add a README" لأن
   عندنا واحد جاهز، ثم اضغط **Create repository**.
4. GitHub سيعرض لك رابط المستودع بالشكل:
   `https://github.com/USERNAME/attar-visits.git`

### ب) رفع الملفات من جهازك (Terminal / موجه الأوامر)
داخل مجلد المشروع (`attar-visits`) نفّذ الأوامر التالية بالترتيب:

```bash
cd attar-visits
git init
git add .
git commit -m "النسخة الأولى المعاد هيكلتها لنظام زيارات المنسّقين"
git branch -M main
git remote add origin https://github.com/USERNAME/attar-visits.git
git push -u origin main
```

استبدل `USERNAME` باسم حسابك على GitHub. عند التنفيذ سيطلب منك GitHub تسجيل
دخول (اسم المستخدم + Personal Access Token بدل كلمة المرور العادية — إن لم
يكن لديك Token اذهب إلى: GitHub → Settings → Developer settings → Personal
access tokens → Generate new token، وأعطه صلاحية `repo`).

### ج) تحديث الملفات لاحقًا
أي تعديل مستقبلي على الكود:
```bash
git add .
git commit -m "وصف التعديل"
git push
```

### د) نشر الموقع مجانًا عبر GitHub Pages (اختياري لكن مفيد جدًا)
1. في صفحة المستودع على GitHub: **Settings** → **Pages**.
2. تحت **Source** اختر **Deploy from a branch**، الفرع **main**، المجلد
   **/ (root)**، ثم **Save**.
3. بعد دقيقة أو دقيقتين سيظهر رابط مباشر مثل:
   `https://USERNAME.github.io/attar-visits/`
   هذا رابط جاهز يشتغل فورًا على أي جهاز (موبايل/حاسوب) وأي متصفح، بدون أي
   إعداد إضافي.

## 5. الأمان وقواعد Firestore — مهم قبل الاستخدام الفعلي

هذا تطبيق **بدون خادم خاص (Frontend فقط)**. تسجيل الدخول فيه هو تحقّق داخل
المتصفح، وليس نظام مصادقة حقيقي مثل Firebase Authentication. هذا يعني:
مفتاح Firebase الظاهر في `js/firebase-config.js` **ليس سرًا** من الناحية
الفنية (Google توضح ذلك رسميًا لمفاتيح الويب)، لكن الحماية الحقيقية لبياناتك
تعتمد بالكامل على "قواعد أمان Firestore".

**خطوات ضرورية قبل تسليم النظام للاستخدام الفعلي:**

1. **طبّق ملف `firestore.rules` المرفق**: من Firebase Console → Firestore
   Database → Rules، الصق محتوى الملف واضغط **Publish**. (بدون هذا الملف،
   أي مشروع Firebase جديد يكون إما مفتوحًا بالكامل أو مغلقًا بالكامل حسب
   وضع الإنشاء).
2. **الأهم — فعّل App Check** (يمنع أي طلب لا يأتِ من نسخة موقعك الحقيقية):
   Firebase Console → **Build → App Check** → أضف تطبيق الويب → فعّل
   **reCAPTCHA v3** → انسخ Site Key → ثم فعّل **Enforce** على Firestore من
   نفس الصفحة. هذا يرفع مستوى الحماية بشكل كبير دون الحاجة لتعديل الكود.
3. **الأشمل مستقبلاً**: ترحيل تسجيل الدخول إلى Firebase Authentication
   الحقيقي (عبر Cloud Function تُصدر Custom Token بعد التحقق من PIN/كلمة
   المرور)، فتصبح قواعد Firestore قادرة على التفريق الحقيقي بين الأدوار.
   هذا يتطلب Cloud Functions (خطوة إضافية خارج نطاق هذا التحديث الحالي).
4. **غيّر كلمة مرور `admin` الافتراضية فورًا** من "الإعدادات → حسابات
   الإدارة" بعد أول تسجيل دخول.

إن كنت تفضّل عدم رفع `js/firebase-config.js` (بمفاتيحك الحقيقية) على GitHub
أصلاً — رغم أنها ليست سرًا حرجًا كما شُرح أعلاه — فعّل السطر الخاص به داخل
`.gitignore` وارفع فقط `js/firebase-config.example.js` كقالب، ثم أنشئ نسخة
`firebase-config.js` يدويًا على كل جهاز تنشر منه.

## 6. الدعم على المتصفحات (Safari / Chrome)

- تم اختبار بنية الكود وميزاته (تسجيل الدخول المشفّر، GPS، الكاميرا،
  التخزين بدون اتصال) لتعمل على أحدث إصدارات **Safari (macOS/iOS)** و
  **Google Chrome (Android/Desktop)**.
- تحديد الموقع GPS والكاميرا يتطلبان **HTTPS** (أو `localhost` للتجربة
  المحلية) — وهو ما يوفّره GitHub Pages تلقائيًا.
- عند فتح الموقع لأول مرة، سيطلب المتصفح إذن الوصول للموقع الجغرافي —
  يجب الموافقة لتفعيل تسجيل الدخول والخروج من الزيارات.

---

## 7. ملاحظة إضافية

هذا النظام مبني بالكامل من طرف العميل (Frontend) دون خادم خاص، وهو مناسب
تمامًا للاستخدام العملي اليومي بعد تطبيق خطوات القسم 5، لكنه يبقى مختلفًا
معماريًا عن نظام له خادم خاص (Backend) بمصادقة حقيقية. إن احتجت لاحقًا
معاودة العمل على الأمان (Firebase Authentication + Cloud Functions) أو أي
ميزة جديدة، الكود الآن منظّم بملفات صغيرة واضحة يسهل الرجوع إليها.
